Audit Context

Conducted a comprehensive web application security audit for Librería On-Line S.A. (fictitious online bookstore), evaluating the security posture of their public-facing web application using automated and manual testing techniques.

The audit focused on identifying vulnerabilities that could compromise user data, session integrity, or application availability — following the EDR (Exploration, Detection, Response) methodology and aligned with OWASP ASVS (Application Security Verification Standard).

OWASP ZAP CVSS v3.1 ISO 19011 OWASP ASVS EDR Methodology

Audit Methodology

Phase 1: Exploration (Reconnaissance)

Application mapping, technology fingerprinting, and attack surface identification using OWASP ZAP’s spider and passive scan capabilities. Target URL sanitized to https://app.example.com/ for confidentiality.

Phase 2: Detection (Active Scanning)

Active vulnerability scanning using OWASP ZAP automated scans, targeting OWASP Top 10 categories: injection flaws, broken authentication, XSS, insecure direct object references, security misconfiguration, and sensitive data exposure.

Phase 3: Response (Analysis & Remediation)

Vulnerability validation, CVSS v3.1 severity scoring, root cause analysis, and structured remediation plan development with priority-based timelines.

Remediation Plan

Critical & High Priority Remediation

  • File Upload: Implement server-side file type validation, restrict upload directories, rename uploaded files, enforce content-type verification
  • CSRF: Implement anti-CSRF tokens on all state-changing requests, validate Referer/Origin headers
  • Session Fixation: Regenerate session ID after authentication, set proper cookie flags (HttpOnly, Secure, SameSite)
  • XSS: Implement output encoding, Content Security Policy (CSP) headers, input validation and sanitization
  • IDOR: Implement server-side authorization checks, validate user ownership before resource access

Medium Priority Remediation

  • Cookie Security: Set HttpOnly, Secure, and SameSite=Strict flags on all session cookies
  • Security Headers: Implement X-Content-Type-Options, X-Frame-Options, and CSP headers
  • ISO 27002 Controls: Align remediation with A.8.25 (Secure development), A.8.8 (Management of technical vulnerabilities), A.5.33 (Protection of records)
